RadF
Data Smoothing

RadF fits a sequence of measured values. One setting controls how closely the fit follows each measurement and how easily its slope can change from one sample to the next.

The central idea

Balance the fit to the data against the bending of the curve

Imagine one measurement sits above its neighbors. A curve that passes through it has zero error at that point, but may bend sharply to reach it. A smoother curve can pass a little below it and accept some error. RadF chooses the fitted heights together by minimizing a weighted sum of two least-squares costs.

The quantity to minimize

J = (1 − k) E + k w B

E · Squared fit errorsAt each sample, take the difference between the fitted height and the measured height. Square these errors and add them up.

B · Squared bendingAt each interior sample, measure how much the slope of the fitted curve changes. Square these changes and add them up.

Choose 0 < k < 1. With w held fixed, k sets the balance. Near zero, the fit follows the measurements closely. Increasing k gives more weight to reducing bends and allows larger departures from the data. As k approaches one, the fit approaches the least-squares regression line. The positive factor w sets the scale of the bending term, so you can choose how much smoothing a given k produces.

How do we find the heights that minimize this sum? Treat each fitted height as an unknown. Take the partial derivative of the total error J with respect to each unknown and set each derivative equal to zero. For n fitted heights this gives n simultaneous linear equations. Solving them gives the smoothed data points. See how one derivative becomes one matrix row.

How RadF measures bending

RadF receives the measured heights y₁, …, yₙ in order, with one horizontal unit per sample. Write zᵢ for the fitted height at sample i. The original formulas called this height xᵢ. The horizontal position comes from the index.

RadF measures bending with the discrete second derivative of the fitted heights. First subtract each height from the next. This first difference gives the slope over one unit interval.

dᵢ = zᵢ₊₁ − zᵢ

Now ask how much that slope changes. At sample i, the incoming slope is dᵢ₋₁ and the outgoing slope is dᵢ. Subtract them in exactly the same way. This gives the second difference, the discrete second derivative on the unit grid.

δᵢ = dᵢ − dᵢ₋₁ = (zᵢ₊₁ − zᵢ) − (zᵢ − zᵢ₋₁)
= zᵢ₊₁ − 2zᵢ + zᵢ₋₁

A straight ramp rises by the same amount at every step, so it contributes zero to the bending sum, however steep its slope.

We can now write both sums in full. Use pᵢ = 1 when every measurement counts equally. A larger pᵢ gives that measurement more weight in the fit.

The least-squares objective in full

J(z)=(1−k)∑i=1npi(zi−yi)2+kw∑i=2n−1δi2

The error sum uses all n measured heights. The bending sum uses the n − 2 interior heights, where a slope is available on both sides.

The two endpoints. With positive sample weights, setting k = 0 gives the data exactly. At k = 1 the data term disappears and every straight line minimizes the remaining cost. To return the unique limiting line at that setting, compute a linear regression directly. The original routines clamp their input to [10−9, 1 − 10−9].

Finding the minimum

Differentiate the total error once for each unknown height

Hold the measurements, the weights and k fixed. Imagine raising or lowering just the first fitted height z₁, holding all the other heights still. The partial derivative ∂J/∂z₁ tells us how the total error changes with that movement. At the minimum this derivative must be zero. The same reasoning applies to every fitted height.

∂J/∂z₁ = 0,   ∂J/∂z₂ = 0,   …,   ∂J/∂zₙ = 0.

Both the error at a sample and the second difference across a triple are linear expressions in the unknown heights. Squaring them makes J quadratic, so differentiating it gives linear equations. With positive sample weights, 0 < k < 1 and w > 0, the data term is strictly convex and the bending term is convex. The simultaneous solution therefore gives the unique minimum.

Follow the first height from the error sum to row 1

Write aᵢ = (1 − k)pᵢ and b = kw. Only two squares in the entire sum contain z₁. One measures its distance from y₁. The other measures the bend in the first triple.

J = a₁(z₁ − y₁)² + b(z₁ − 2z₂ + z₃)²
+ terms independent of z₁.

Differentiate with respect to z₁. Both squares contribute a factor of two, which we can divide out. Set the result to zero, then move the known measurement term to the right.

½ ∂J/∂z₁ = a₁(z₁ − y₁) + b(z₁ − 2z₂ + z₃) = 0
(a₁ + b)z₁ − 2bz₂ + bz₃ = a₁y₁.

The last line is the first row of the linear system. Its first three coefficients are a₁ + b, −2b and b. All later columns in that row are zero.

Repeat the differentiation for the remaining heights

A height zᵢ well inside the curve belongs to three bends. Its coefficient is +1 in the bend to its left, −2 in its own bend, and +1 in the bend to its right. Its derivative equation is

½ ∂J/∂zᵢ = aᵢ(zᵢ − yᵢ) + b(δᵢ₋₁ − 2δᵢ + δᵢ₊₁) = 0.

Expand the three second differences and the coefficients of the five neighboring heights are 1, −4, 6, −4, 1, each multiplied by b. The data term adds aᵢ to the middle coefficient and puts aᵢyᵢ on the right.

At the ends there are fewer triples to differentiate. The first point belongs to just one bend, and the second point belongs to two. Counting those contributions gives the boundary rows below. Both end heights are free to move.

Solve the resulting linear system

Read across each row of the table, multiplying each coefficient by the height above it. A dash marks a position outside the grid. Collect these coefficients in the n × n matrix A, the unknown heights in the vector z, and the known right sides in the vector r, with rᵢ = aᵢyᵢ.

A z = r

This is the familiar A x = b linear system. The original notes called the unknown heights x. Here z denotes those same heights and r denotes the right-hand side, leaving b = kw for the scalar bending weight. Each row of A already contains the coefficients of one differentiated equation. Solve the system once by Gaussian elimination, QR factorization or, using its symmetry and narrow bands, banded Cholesky factorization. The entries of the solution are the smoothed heights in sample order.

The same solution in matrix notation

Let P be the diagonal matrix of sample weights. Let D have one row per triple, with entries (1, −2, 1) in its three consecutive columns and zeros elsewhere. Then Dz collects the bends and the normal equations are

[(1 − k)P + kw DᵀD] z = (1 − k)P y.

For any vector v, its quadratic cost in this matrix is (1 − k)Σpᵢvᵢ² + kw‖Dv‖². With nonnegative weights both terms are nonnegative. For both to vanish, v must be a straight line that is zero at every positively weighted position. Two distinct such positions force the entire line to be zero. This gives a unique solution and justifies a Cholesky solve.

The smoothing parameter

Why did k need so many nines?

Divide the cost by 1 − k. This leaves the fitted curve unchanged and reveals the multiplier that actually controls the cost of bending.

λ = w k1 − kand hencek = λw + λ

In basic RadF, w = 1. A bend multiplier of 499 therefore requires k = 0.998. The normalized method moves the middle of the control to a different place. It sets w = n² and calls the input kₙ. At its midpoint, kₙ = ½, the multiplier is already n². On the same grid the two versions give exactly the same curve whenever their multipliers agree.

kₙ = kk + n²(1 − k)for the same fit as basic RadF

The archived annual series has 156 measurements. Its raw setting of k = 0.9999 translates to kₙ ≈ 0.2912, explaining the saved setting of 0.29. The archived comparison also labels the monthly fit with kₙ = 0.98. The annual and monthly settings already tell us that one normalized value did not serve both grids in that comparison. The reference implementation below reproduces both archived annual fits to within 8 × 10−11 at every sample. The notes establish the choice w = n² and show the comparison. They give no derivation of the exponent. This change makes those high raw settings easier to enter, while the new control still has a nonlinear response.

How “Best Kn” finds a setting for the data at hand

How much more does the fit depart from the measurements if we turn up the smoothing by one small step? Roland Adorni’s “Best Kn” routine in RadFSmoothingForm.cs tries a series of normalized settings. At each one it adds up the squared distances between the fitted heights and the measurements. It selects the setting where that total is increasing most slowly.

Applying the rule to the archived error tables gives 0.35 for the annual average of 12 temperature stations, 0.51 for the historical solar series and 0.31 for the TIM solar series. Here “best” has a specific meaning. Among the settings tried, a small increase in smoothing around the selected value costs the least additional squared error. The result depends on the data and provides a starting point for further adjustment.

Reproduce the selection rule

Write qⱼ = j/100 for a trial value of kₙ. Fit the data at each trial setting and record Eⱼ, the sum of squared residuals. For each candidate, average the increase in error on the step into it and the step out of it.

Eⱼ = ∑ᵢ (zᵢ(qⱼ) − yᵢ)²
Δⱼ = ½[(Eⱼ − Eⱼ₋₁) + (Eⱼ₊₁ − Eⱼ)] = ½(Eⱼ₊₁ − Eⱼ₋₁)

The original search compares candidates from j = 3 through 96 inclusive, so the neighboring errors needed run from j = 2 through 97. Select the candidate with the smallest Δⱼ, keeping the first in a tie. Return qⱼ and its fitted curve.

Record length

What happens when you append 100 points?

Take a series at x = 0, 1, …, 99. Tomorrow there are 100 more measurements, continuing through x = 199. Every step is still one unit. A ripple that repeats every ten samples still has the same width. How do we give that ripple the same amount of smoothing?

With basic RadF, keep the same k. Each measurement adds one data term, and each new triple adds one bend term with exactly the same coefficients as before. The ratio λ = k/(1 − k) contains no sample count. Interior ripples of a given width therefore face the same local smoothing rule in both records.

There is one visible change even with fixed λ. The old endpoint at x = 99 used to belong to just one triple. Now two more triples reach across the join and the fit can use later observations. Since all heights are solved together, earlier values can move too. This influence is usually strongest near the join and can reach farther back under strong smoothing.

With normalized RadF, fixed kₙ has a different meaning. Doubling n multiplies w = n² by four, so it multiplies λ by four everywhere. That is the explicit count dependence in the original normalized routine. Unit-sum sample weights can also introduce count dependence, as shown in the weights table above.

Calibrate the weight once, then keep it

Basic RadF uses w = 1, but any fixed positive weight gives the same independence from record length. With unit spacing, equal sample weights and a fixed control setting, the bend penalty λ = wk/(1 − k) contains no sample count. Exposing both k and w lets one parameter control the fit and the other set its useful range.

  1. On a reference series of n₀ samples, start with w₀ = n₀². Run Best Kn once and call the selected setting q.
  2. Save w = w₀ q/(1 − q). This is the selected fit’s bend penalty. At kₑ = 0.5, the factor kₑ/(1 − kₑ) equals one, so the new control reproduces that fit exactly in the mathematical model.
  3. For this series and later extensions at the same spacing, call radF(y, ke, w) with the saved weight. Move kₑ below or above the midpoint for less or more smoothing.

For the 156 annual measurements the search chose q = 0.35, giving w = 156² × 0.35/0.65 = 13 104. Keep 13 104 when the next year arrives. Run a fresh calibration only if you want the midpoint to track a newly selected fit.

Can we hold the control at 0.5 and search directly over weights?

Yes. At the midpoint λ = w, so one trial weight represents one trial fit. To reproduce the archived selection, take the original trial settings qⱼ = j/100, convert each to wⱼ = w₀ qⱼ/(1 − qⱼ), and fit at kₑ = 0.5. Compare neighboring residual sums in the original trial order. The two searches then visit the same curves and use the same score. Equal increments in w would space the trials differently and could select a different midpoint.

This JavaScript helper uses the curve solver below. Run it on the reference measurements and save the returned number.

function calibrateRadFWeight(reference) {
  const initialWeight = reference.length ** 2;
  const errors = [];
  const weightAt = j => initialWeight * j / (100 - j);

  for (let j = 2; j <= 97; j++) {
    const fitted = radF(reference, 0.5, weightAt(j));
    errors[j] = fitted.reduce((sum, z, i) => sum + (z - reference[i]) ** 2, 0);
  }

  let bestIndex = 3;
  let bestIncrease = Infinity;
  for (let j = 3; j <= 96; j++) {
    const increase = (errors[j + 1] - errors[j - 1]) / 2;
    if (increase < bestIncrease) {
      bestIndex = j;
      bestIncrease = increase;
    }
  }
  return weightAt(bestIndex);
}

More generally, write s for the new control value kₑ. Choose any familiar raw setting k₀ and the position s₀ where you want it on the control, both strictly between zero and one. Match their bend penalties once to calculate the fixed weight.

w = k₀1 − k₀ · 1 − s₀s₀

With the paper’s solver, call radF(y, s, w). With the original RadFSmoothing, which fixes its internal weight at one, convert the control value s to raw k before the call. Both routes solve the same equations, to numerical precision and within the original routine’s clamp limits.

k = ws1 − s + ws

If your favorite setting already comes from normalized RadF on a reference record of n₀ samples, the calibration is simpler. Fix w = n₀² once and use the old kₙ directly as s. In either version, a longer unit-spaced record keeps the same control calibration.

Can equal control steps remove equal amounts of a ripple?

Yes, if we specify the ripple whose height we want the control to measure. Choose a period P ≥ 2 in samples. Then choose the fixed weight below. On an infinite unit grid with equal sample weights, a sinusoidal ripple of that period retains exactly the fraction 1 − s of its amplitude. For instance, s = 0.25 removes a quarter of its amplitude and s = 0.5 removes half. This also describes the interior of a long record away from end effects.

w = 116 sin⁴(π/P)

To see why, take second differences of a sine wave of period P. Each result is the original wave multiplied by −4 sin²(π/P). In the normal equations DᵀD applies this factor twice, giving q = 16 sin⁴(π/P). The fit therefore retains the fraction 1/(1 + λq). Substituting w = 1/q and λ = ws/(1 − s) gives 1 − s. Other periods respond according to their own q, so “half smoothed” needs a chosen scale. This calibration follows from the equations and is an option for new implementations.

If your implementation only accepts the original normalized parameter

First calculate λ = n₀² kₙ/(1 − kₙ) on the reference record. For a new length n, pass kₙ,new = λ/(n² + λ) to RadFKnSmoothing. The two count factors cancel, giving the intended fixed strength. The equivalent basic setting is k = λ/(1 + λ).

A different experiment · taking more samples over the same interval

Imagine taking twice as many measurements of the same stretch of curve. Each horizontal step is now about half as long. A smooth bend then produces about one quarter of its old second difference. Squaring that difference leaves only one sixteenth of the old cost per triple. Keeping the same physical smoothing length therefore calls for about sixteen times the bend multiplier. The n² rule supplies about four times.

A rule tied to horizontal distance

Let h be the distance between adjacent samples. On a smooth curve, the second difference approximates h²z″(x). For equal sample weights, multiplying the discrete cost by h turns its sums into approximations to integrals. The bend term carries an extra factor h⁴, so its strength in physical coordinates is λh⁴.

λnew = λref(hrefhnew)4

Choose a reference spacing href where you like the behavior of the control, and keep its wref. At a new spacing use w = wref(href/h)⁴ with the same slider setting. For compatibility with an existing normalized fit, set wref = nref². On a fixed interval including both endpoints, the spacing ratio is exactly (n − 1)/(nref − 1). This is an extension to the original routines.

This adjustment preserves the physical smoothing scale approximately for well-resolved features. Finite-grid end effects and newly resolved detail can still change fitted heights.

Scope. This derivation uses equal or mean-one comparable sample weights and a uniform grid. With equal unit-sum weights the effective multiplier is nλ, so apply the spacing rule to that product. With irregular horizontal positions the raw second difference measures bending in sample index. Resample to an even grid or derive the penalty using the actual spacings before interpreting the line or smoothing length in physical coordinates.

Implementation

Build the system one triple at a time

Start with the data term on the diagonal, Aᵢᵢ = aᵢ, and the right side rᵢ = aᵢyᵢ. All other entries start at zero. For each consecutive triple, add the following block to its three rows and matching three columns. Where blocks overlap, add their entries.

b ×1−21−24−21−21

This block is the outer product of (1, −2, 1) with itself. Adding every triple once builds all five row types, including the two ends. Solve Az = r. Because the matrix is symmetric and has just two bands on either side of the diagonal, a banded Cholesky solver uses linear time and storage.

A five-sample correction. All three original curve routines accept five samples. At exactly that length their assembly loop omits the coupling between the second and fourth heights. Both A₂₄ and A₄₂ should equal b. The table, the block construction and the implementation below include those entries. An easy check is to feed in any straight line. Every fitted height should reproduce its input to numerical precision.

Copyable JavaScript implementation

The function returns the fitted heights in sample order. Use ordinary arrays. Call radF(y, k) for basic RadF or radF(y, kn, y.length ** 2) for the original normalized version. For a weighted fit pass radF(y, k, 1, p) with p normalized as above. Very large bend multipliers can make the system ill-conditioned in floating-point arithmetic.

// y holds the measured heights. p holds optional, already normalized weights.
function radF(y, k, w = 1, p = Array(y.length).fill(1)) {
  const n = y.length;
  if (n < 5 || p.length !== n || !y.every(Number.isFinite) ||
      !p.every(v => Number.isFinite(v) && v >= 0) ||
      p.filter(v => v > 0).length < 2 ||
      !(k > 0 && k < 1 && w > 0 && Number.isFinite(w))) {
    throw new RangeError("Check the samples, weights and smoothing parameter.");
  }

  // Store the main diagonal and the two bands immediately below it.
  const b = k * w;
  const diag = p.map(v => (1 - k) * v);
  const rhs = diag.map((v, i) => v * y[i]);
  const near = Array(n).fill(0);
  const far = Array(n).fill(0);
  for (let i = 0; i < n - 2; i++) {
    diag[i] += b;
    diag[i + 1] += 4 * b;
    diag[i + 2] += b;
    near[i + 1] -= 2 * b;
    near[i + 2] -= 2 * b;
    far[i + 2] += b;
  }

  // Cholesky factorization A = L Lᵀ, reusing the three bands.
  // Solve L u = rhs in the same forward pass.
  for (let i = 0; i < n; i++) {
    if (i >= 2) far[i] /= diag[i - 2];
    if (i >= 1) near[i] = (near[i] - far[i] * near[i - 1]) / diag[i - 1];
    const pivot = diag[i] - near[i] ** 2 - far[i] ** 2;
    if (!(pivot > 0 && Number.isFinite(pivot))) {
      throw new RangeError("No positive pivot at this precision.");
    }
    diag[i] = Math.sqrt(pivot);
    if (i >= 2) rhs[i] -= far[i] * rhs[i - 2];
    if (i >= 1) rhs[i] -= near[i] * rhs[i - 1];
    rhs[i] /= diag[i];
  }

  // Solve Lᵀ z = u from the last sample to the first.
  for (let i = n - 1; i >= 0; i--) {
    if (i + 2 < n) rhs[i] -= far[i + 2] * rhs[i + 2];
    if (i + 1 < n) rhs[i] -= near[i + 1] * rhs[i + 1];
    rhs[i] /= diag[i];
  }
  return rhs;
}

Surface smoothing

From a curve to a grid of heights

Imagine a height measured at each crossing of a rectangular grid. Look along one row and you see an ordinary curve. Turn through a right angle and each column is another curve. RadF2DSmoothing chooses one height at each crossing, balancing closeness to its measurement against bending in both directions. Each crossing has a single fitted height shared by its row and column.

Count each horizontal and vertical bend once

Write Y for the measured heights and Z for the fitted heights. Number rows r = 1, …, R and columns c = 1, …, C. The original routine requires R, C ≥ 5, gives every sample equal weight, uses w = 1, and clamps k to the same open-range limits as the curve routines.

Hr,c = Zr,c−1 − 2Zr,c + Zr,c+1
Vr,c = Zr−1,c − 2Zr,c + Zr+1,c

The horizontal bend H exists wherever there is a neighbor on either side in the row. The vertical bend V needs neighbors above and below. Square these bends and add them to the squared errors at all the crossings. With a = 1 − k and b = kw, minimize

J(Z) = a ∑all cells (Zr,c − Yr,c)² + b ∑horizontal triples Hr,c² + b ∑vertical triples Vr,c².

Differentiate with respect to each grid height

Apply the same minimum condition to the whole surface. Hold every other fitted height fixed and set ∂J/∂Zr,c = 0 at each crossing. On an R × C grid this yields RC simultaneous linear equations for RC unknown heights. The derivative at each crossing supplies one row of the surface matrix A.

Deep inside the grid, the one-dimensional bend coefficients contribute 6b to the central height from its row and another 6b from its column. Each of the four immediate neighbors contributes −4b and each of the four neighbors two steps away along the axes contributes +b. Let S₁ and S₂ denote the sums of those heights at one and two steps, respectively. The collected Maxima equation is

(a + 12b) Zr,c − 4b S₁ + b S₂ = a Yr,c.

At an edge or corner, read the corresponding one-dimensional row from the coefficient table for each axis. Add only the bend contributions from the two directions. Include the data term a on the diagonal just once. For instance, the top-left corner equation is

(a + 2b) Z₁₁ − 2b (Z₁₂ + Z₂₁) + b (Z₁₃ + Z₃₁) = a Y₁₁.

What survives the strongest smoothing?

A surface has zero bend cost when every row and every column is straight. Row slopes can still change linearly from one row to the next. For example, Zr,c = rc is straight in each direction and forms a saddle when viewed diagonally. The original objective measures only the two axis directions, so this saddle survives at every setting.

Zr,c = α + βr + γc + ηrc

These are all the zero-bend surfaces. As k → 1, the solution approaches the least-squares fit of these four coefficients to the data. Exactly at one, every such surface gives zero cost. As with the basic curve routine, extending a unit-spaced grid at fixed k keeps the local bend penalty constant. New observations can change the fit near the old borders.

Copyable Python implementation of the joint surface solve

For an axis of length m, let Dₘ take consecutive second differences and set Bₘ = DₘᵀDₘ. The full equations, divided by a, can be written with the heights in their original rectangular layout.

Z + λ(BRZ + ZBC) = Y, λ = b/a.

The NumPy function below diagonalizes each axis matrix. In those coordinates a mode with row eigenvalue μ and column eigenvalue ν is divided by 1 + λ(μ + ν). Two successive one-dimensional fits would divide by (1 + λμ)(1 + λν) and produce a different surface. The joint solve also avoids storing a dense matrix with RC rows and columns.

def radf2d(heights, k):
    """Fit one height at every cell on a rectangular, unit-spaced grid."""
    import numpy as np

    y = np.asarray(heights, dtype=float)
    if y.ndim != 2 or min(y.shape) < 5 or not np.isfinite(y).all():
        raise ValueError("Supply a finite grid with at least 5 rows and 5 columns.")
    if not 0 < k < 1:
        raise ValueError("Use a smoothing parameter strictly between 0 and 1.")

    def bending_modes(size):
        d = np.diff(np.eye(size), n=2, axis=0)
        values, vectors = np.linalg.eigh(d.T @ d)
        values[:2] = 0.0  # Constant and linear modes have exactly zero bend.
        return values, vectors

    row_values, u = bending_modes(y.shape[0])
    col_values, v = bending_modes(y.shape[1])
    penalty = row_values[:, None] + col_values[None, :]
    modes = u.T @ y @ v
    return u @ (modes / (1 + (k / (1 - k)) * penalty)) @ v.T
